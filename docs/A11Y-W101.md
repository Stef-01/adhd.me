# Accessibility re-run (W101) — WCAG 2.1 AA

W49 established the bar: axe-core over every surface, zero violations, a finding fixed or
explicitly ruled but never ignored. Year 2 added twelve surfaces and rebranded the product.
This is the re-run W49 required once that happened.

**Result: zero violations across every surface, including the ones that had never been
scanned.**

## What the re-run actually found

Not a contrast failure — a **coverage** failure, which is the more dangerous kind because the
suite was green the whole time.

The test named `sign-in and onboarding pass WCAG A/AA` had, since W49, only ever scanned
sign-in. Onboarding was in the title and not in the assertions. It is the first authenticated
form a practice ever meets, and reaching it needs a state the other tests never sit in — a
signed-in session with no practice yet — so it fell through the gap between the sign-in test
(signed out) and the console test (signed in, practice created).

It passes, which is why nobody noticed. A green suite that does not test the thing its own
test name claims is worse than a red one.

with the scanned step; the wizard's steps differ in fields, not in structure.

## Sampling discipline carried over

Two W49-era fixes stay load-bearing and are worth restating, because both were originally
diagnosed as product bugs and were not:

- **Scan the settled page.** `prefers-reduced-motion` is emulated before every scan. The care
  finder's screens fade in over 260ms, and axe caught mid-fade measures a composited colour —
  it reported 4.46:1 against tokens that measure 4.7:1 at rest. That made the suite pass in
  isolation and fail under load.
- **Assert the title before scanning.** axe reads `document-title` once, instantaneously, so
  a server action's revalidation swap could be caught mid-flight on a page that has a title
  pinned.

Neither weakens the bar. Both remove a measurement artefact that was producing false
failures, and a suite that cries wolf gets ignored.

## Known limitations, unchanged from W49

- The severity and channel `<select>` controls remain native, deliberately: native is the
  most accessible option and no custom dropdown exists in the product.
- Booking-page focus is not programmatically moved to the confirmation heading after the
  server action re-renders. Acceptable for a full page content change; revisit if the flow
  becomes multi-step.
- **Post-G2 requirement stands.** These scans run against the synthetic build. The real-data
  console must re-run this suite unchanged before G2 opens — which is what made W101 a unit
  rather than a chore.
