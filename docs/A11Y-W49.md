# Accessibility pass (W49) — WCAG 2.1 AA

Two halves, per the unit's verify gate:

- **Automated**: `e2e/a11y.spec.ts` runs axe-core (WCAG 2.1 A/AA rulesets) over every
  console surface, sign-in, the patient booking states (offer, confirmation, invalid
  link), and the public pages. Zero violations is enforced in CI-runnable e2e — a
  regression fails the suite.
- **Manual**: the checklist below, walked on the production build. Items the automated
  scan cannot judge.

## Findings fixed this unit

| Finding | Where | Fix |
|---|---|---|
| Secondary text at ~2.4:1 contrast (`text-stone-400` on white) — fails AA 4.5:1 | 14 files across console, booking, landing, demo | Swept to `text-stone-500` (4.95:1 on white, 4.75:1 on stone-50) |
| `<title>` transiently absent after the sign-out client-side redirect | /console/signin | Explicit page metadata (`Sign in — Meherr`) — also satisfies WCAG 2.4.2 distinct titles |

## Known limitations / future items

- The severity `<select>` on complaints and channel `<select>` rely on native controls —
  deliberately (native = most accessible); no custom dropdowns exist in the product.
- Booking-page focus is not programmatically moved to the confirmation heading after the
  server action re-render; screen readers re-announce the page. Acceptable now (full page
  content change), revisit if the flow becomes multi-step.
- Automated scans run on the synthetic-data build; the real-data console (post-G2) must
  re-run this suite unchanged.
